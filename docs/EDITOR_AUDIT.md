Branch `editor-audit` (= `editor` c84da10). No engine source was changed. Screenshots are in
`/private/tmp/claude-501/-Users-himanshu-codes-game-engine/e41f472a-4233-4b7f-bb38-ab5ae25281bd/scratchpad/audit/`
(step files `a.json`, `b2.json`, `c.json` next to them). Runs: `editor_demo` (assets root pointed at

## 1. Findings, ranked

### P0: blocks basic use

**P0-1. Clicking a code-built object (a building) selects nothing.** Screenshots `b02_house_selected.png`,
`b03_outliner.png`, `b01_town_before.png`. Verified: `editor.select {ids:[<house>]}` sets the selection,
`editor.state` right after reads `selection: []`, Details says "Nothing selected", no gizmo, no outline,
and the Outliner is **empty** (every entity of `pcg_town` is unnamed).
Cause (two parts, both must be fixed):
1. `src/editor/picking.rs:99-117` `pick_root` returns the nearest `LevelEntity`, else the topmost *named*
   ancestor, else the raw hit entity. A building spawned as `(Mesh3d, MeshMaterial3d, Transform, Scenery)`
   has neither, so the raw mesh entity is selected. That is fine in itself.
2. `src/editor/backend.rs:130-170` `build_node` only lists entities that have a `LevelEntity` or a `Name`
   (and drops `INTERNAL_NAMES` / prefixes such as `cell `, `chunk `, `pcg `, `World`). Then
   `crates/editor-ui/src/lib.rs:595` `self.selection.retain(|id| nodes.info.contains_key(id))` removes every
   selected id that is not in the tree and writes the shortened list back with `backend.set_selection`.
   So the click selects for one frame and the UI un-selects it. Anything unnamed, merged by the
   Scenery merge, a PCG instance, a terrain chunk, or named like an internal prefix behaves the same.
Fix (engine): selection must not depend on the tree. (a) Drop the `retain` against `nodes.info`; keep only
"entity no longer exists" (the backend already does that in `selection()`). (b) Give every pickable generated
entity a synthetic tree row or, better, show a "Selection" header row above the tree for ids not in the tree
(name = `Name`, else `<Mesh> <index>`), so something is always highlighted. (c) Details for a generated
entity: banner "Generated by `<origin>`. Read-only here. To edit it, make it a level entity" and a button
**Convert to level entity** (spawns a `LevelEntity` copy with the same mesh/material primitive when it is a
`Primitive`; otherwise disabled with the reason). (d) Selection outline (the orange gizmo box exists for level
entities; use the same `Aabb` box for generated ones). (e) The gizmo stays off for generated entities but the
Move tool should say why in the status bar: "Read-only: generated by code".
What the game must do (Pacenote): buildings have to be level entities or placeables to be editable. Concretely
make each building root `(LevelEntity { id }, Name("Building 12"), BuildingSpec { seed, kind, floors, ... })`
with the generated mesh as a *child* the builder rebuilds from `BuildingSpec` (a `#[derive(Reflect)]`
component registered with `register_type` and `register_placeable`). Then click selects the root
(pick_root already walks up to `LevelEntity`), Details shows the spec, edits rebuild, and Save stores the spec,
not the mesh. Merged static geometry must keep an `Entity` -> source map (or skip merging in editor mode).

**P0-2. Content Browser tiles form a diagonal staircase.** Screenshot `a07_content_mixed.png` (also `a01`).
Cause: `crates/editor-ui/src/content.rs:163` uses `ui.horizontal_wrapped` with 98 px tall tiles. egui's wrapped
row is laid out with `Align::Center` and a row height taken from the first item; each later tile is centred on
the row, so it moves down by half the height difference and wraps late. Fix: lay out the grid by hand: `cols =
max(1, floor((avail_w + gap) / (tile_w + gap)))`, allocate a full-width `Rect` per row, `rect.min + (col *
(tile_w+gap), row * (tile_h+gap))`, or `ui.with_layout(Layout::left_to_right(Align::TOP).with_main_wrap(true))`
with `allocate_exact_size`. Use `ScrollArea::show_rows` over rows so 5 000 assets stay cheap. Also stop the
panel being only 230 px tall by default (see P1-3).

**P0-3. Every file shows a Place button; Place on a sound errors and the toast appears twice.**
Screenshot `a07_content_mixed.png`; control reproduction `editor.place {path: engine_idle_bay.ogg}` returns
"`engine_idle_bay.ogg` is not a model (glb/gltf)".
Causes: `content.rs:188` `if e.kind != AssetKind::Folder` draws Place for Audio, Texture, Level, Logic,
Script, Other. `content.rs:197-219` also makes double-click = Place for any file. Backend refuses at
`src/editor/backend.rs:538`, the UI turns it into `say_error` (`lib.rs:742`) which pushes a toast
(`lib.rs:711-714`). Why twice (not reproducible offscreen): ashlar `Toasts::push` never de-duplicates, and the
Place button (50x18) sits on top of a tile that also senses double-click (`content.rs:197`), so a quick double
press can queue `Req::Place` from the button and again from `activate`. Either way two identical toasts follow.
Fixes: (1) show an action per kind: Model = "Place" (drag to viewport), Level = "Open", Logic = "Open in
Blueprint editor" (or "Attach to selection"), Script = "Open", Audio = play preview + drag onto an entity to add
an audio emitter, Texture = preview, Material = assign to selection. No button on kinds with no action; no
button at all on idle tiles (show on hover, like UE). (2) `Req::Place` is only generated for `AssetKind::Model`.
(3) De-duplicate toasts with the same text within 2 s (wrap `say_*`), and use the toast for the first line only;
long reasons go to the Output log. (4) `obj` is classed as Model (`backend.rs:414`) but loads as `#Scene0`, which
only glTF has: either remove `obj` or load it as a mesh.

**P0-4. "Where is what, how do I set blueprints": there is no logic workflow.** Screenshot `a06_logic.png`.
The Logic tab is a hard-coded 3-node demo (`crates/editor-ui/src/logic.rs:12-56`: `Time -> Multiply -> Spin`,
`&'static str` nodes). It is not connected to `logic-core`, any `.logic.ron`, the selected entity or the
runtime. Pins are labelled "in"/"out" and clipped ("ou"). Nothing can be created, loaded, saved, validated.
Selecting the Crate does not change it. The real runtime already exists (`crates/logic-core`: 33 node kinds,
typed pins, `GraphError` with node/pin, `Logic { graph }` component, `logic.fire`, diagnostics). Fix: section 4.

### P1: causes confusion or wasted time

**P1-1. Details is hidden behind the Tool tab.** Screenshots `c01`, `c07`: with the Road or Dressing selected
the right dock shows "No tool selected", because `Tool` is a tab next to `Details` (`lib.rs:92-96`) and the
persisted layout kept it in front. Selection never brings Details forward. UE shows Details permanently;
tool settings belong in the Modes panel / tool header, not in a tab that hides Details.

**P1-2. Place is split in two panels on opposite sides.** `c06`: Place palette (left tab, `place.rs`) arms the
tool, the tool's `type_path` is a raw text field on the right ("world_editor_demo::EventMarker", cut off), and
the hint on the right says "Pick a type in the Tool panel" while the type list is on the left. Models are only
found under `library/` (`place.rs:18-33`), so `rallycar.glb` in `models/` is only placeable from Content, and the
empty state says "Games register types with register_placeable" (`a03`), not "drag a model from Content".

**P1-3. Content area is 230 px tall and mixes folder tiles with files with no filters.** `lib.rs:85-86`
`FixedSecond(230.0)`. Fits ~1 row. No type filter, no list/tile switch, no thumbnails for models/textures,
no folder tree, no breadcrumb back-navigation affordance (the root link is blue "assets" text), no sort, no
right-click menu, no drag from tile to viewport, no create-asset menu.

**P1-4. Tools are named inconsistently and mixed in one toolbar.** `chrome.rs:151-190` puts Play, Select, Move,
Rotate, Scale, Spline, Sculpt, Paint, Foliage, Place, Undo, Redo, Save in one row. Move is the default tool,
so the first click on an object also shows a gizmo you did not ask for; UE and Unity default to Select/Move
with the gizmo only on selection. "Spline" (a world tool) sits next to "Scale" (a transform tool). Play sits
left of everything, UE puts Play in the centre of the top bar.

**P1-5. Output panel is empty and hides errors.** `a05`: filter row shows Errors / Warnings / Info / Debug with
only Info on; place errors, edit errors and logic diagnostics (`LogicDiagnostics`) never appear (`control place`
errors are returned to the caller only: `editor.diagnostics` was `[]` after the failed place). No message log
with click-to-select, no clear/search, no source filter (Build / Logic / Editor / Game).

**P1-6. Help window is clipped.** `a08`: "Controls and shortcuts" is a fixed-height window that ends mid-row at
"Cmd+Shift+S"; the rest is behind a scroll that is not obvious. Command palette (`a09`) shows 10 of ~25 commands
and no tool/asset/entity search.

**P1-7. Generated objects are second-class everywhere.** Outliner folds them into one "Generated (n)" folder
(`outliner.rs:150-154`), Details only says "Generated by code: read-only" (`details.rs:94-96`), and whole
categories vanish (`INTERNAL_NAMES`, `INTERNAL_PREFIXES`, `under_level`, unnamed). The owner cannot tell why
something cannot be selected or edited, nor who built it.

**P1-8. No way to attach logic to an object.** `details.rs:54-56` "Add component" is a flat reflect list of every
`Default` type. There is no "Add Logic", no list of existing graphs, no "Open graph", no variables.

**P1-9. No World Settings / Project Settings / Editor Preferences.** Sun, sky, fog, exposure (`docs/LOOK.md`),
terrain, streaming, quality, input actions live in resources and `look.*` commands but not in a settings
window. The only prefs are View > Show all scenery and the control hint. `View` menu lists panels as checkboxes
but there is no named layout (Default / Terrain / Logic).

**P1-10. Status feedback.** Selected count says "1 selected" while Details says "Nothing selected" (`c01`,
`c07`: selection of an entity that the tree does not show). The viewport overlay speaks of "Perspective Speed
Snap World" with no hint what they are, and the control hint reads "1-4 tools" while tools 5-9 exist.

### P2: polish

- P2-1 Lamp/Sun light markers are tiny "spoon" glyphs (`a01`), no billboard icons, no light colour tint.
- P2-2 Raw field names (`snap_to_ground`, `pick_target`, `noise_scale`) as labels (`c02`, `c03`); no tooltips, no
  units, no section grouping (Brush / Falloff / Advanced), no reset-to-default arrow.
- P2-3 Spline tool: `point` is an integer field (`c02`): selecting a point should be a click; show the list of
  points with width/bank, not `-1`.
- P2-4 Place palette "Event marker" has no icon, no drag, no preview (`c06`).
- P2-5 Outliner folders are by kind (Lights, Meshes ...) instead of the level hierarchy; the flat kind folders hide
  parenting and cannot hold user folders. (UE: user folders + type column.)
- P2-6 No viewport toolbar for view modes (Lit / Unlit / Wireframe / Collision), camera bookmarks, stats toggle,
  perspective/ortho, a "Show" menu (Terrain, Splines, Foliage, Lights, Gizmos).
- P2-7 Dragging dividers stretches the old image for four frames (`docs/EDITOR.md` known gaps).
- P2-8 Undo history is only "Undo: label" in the status bar; no History panel.
- P2-9 Hint overlay `x` button is a bare lowercase x; the axis gizmo is not clickable to snap the camera to an axis.
- P2-10 `Save` is level-only; saving terrain/foliage changes happens silently and Play always rebuilds the game.

Design principles taken from both: (1) the Details/Inspector is always visible and always shows the selection;
(2) tools live in a Modes switcher, not mixed with transform tools; (3) every asset kind has a double-click
action and its own editor tab; (4) the Blueprint / script editor is a tab on the main area, not a drawer; (5) one
Output / Message log for everything, with clickable locations; (6) World Settings and Project / Editor settings are
windows reachable from the menu and from the toolbar.

## 4. Logic ("Blueprint") workflow, end to end

Model: logic-core `Graph` (`nodes`, `flow`, `data`, `defaults`, `pos`) is the file format already, so the editor
edits `Graph` directly; no second format. `Logic { graph: "logic/<name>.logic.ron" }` attaches it.

### 4.1 From an actor
1. Select an object. Details shows a **Logic** section (empty state: "No logic. Add a behaviour with graphs").
2. `+ Add Logic` opens a small popup: `New graph from template` (Empty, Trigger zone, Door, Pickup, Timer, On
   action key, Event start), `Existing graph...` (list of `logic/*.logic.ron` with search), `Script...` (list of
   `scripts/*.ruspy`).
3. New: asks for a name (default `<EntityName>_logic`), creates `assets/logic/<name>.logic.ron` with the template
   (valid graph, even if only `Start -> Log`), inserts `Logic { graph }` on the selected entity (an `Op::Batch` so
   one undo removes the component; the file stays, Details offers "Delete file"), and **opens the graph tab** and
   focuses it. The backend call is `create_logic(name, template) -> path` (writes the file) plus the normal
   `SetComponent` op for `Logic`.
4. The Details `Logic` row: graph name, `Open` (focus tab), `Detach`, `Show in Content`, and a status dot
   (green = compiled/loaded, red = errors with count, grey = not running in the editor).
5. The Content Drawer: double-click a `.logic.ron` = open the tab; drag it onto an entity = attach; right-click >
   `New Logic graph`.

### 4.2 The Logic editor tab (one per graph; opens in the document area)
Layout (wireframe in 5.2). Parts:
- **Toolbar**: `Compile` (validate; runs `logic_core::compile`), `Save` (Cmd+S), `Revert`, `Find` (Cmd+F, nodes by
  name/pin), `Play/Simulate` toggle (runs the graph in the editor world, paused time stays off: uses
  `logic.fire` events; see 4.6), `Zoom to fit`, `Comment`, `Layout` (auto-layout columns by depth),
  `Show minimap`. Dirty dot on the tab title; Cmd+S saves the graph when the tab has focus, else the level.
- **My Logic panel (left)**: sections `Events` (one row per event node, click to jump), `Variables`, `Scripts`,
  `Messages` (names used by `Emit`/`Message`). Variables map to existing storage: a variable is a named
  `Get`/`Set` path on a **component field** (`Door.open`) or a graph-local value (new `Var` node pair: `GetVar`,
  `SetVar`, stored in the graph file as `vars: [(name, Ty, default)]`; needs a logic-core addition, WP-C).
  `+` adds a variable with type dropdown; drag a variable onto the canvas for Get / Set (Alt = Set).
- **Canvas** (egui-snarl): pan = two-finger scroll or middle/space-drag, zoom = pinch or Cmd+scroll, box select =
  drag on empty space, `F` frame selection, `Cmd+D` duplicate, `Delete`, `C` comment around selection, `Cmd+Z`
  undo through the same ashlar history (an `Op::GraphEdit` carries `before`/`after` of the whole `Graph` RON, merge
  key per drag). Mini-map bottom-right. Grid snap 16 px.
- **Pins**: exec pins are white arrows; data pins coloured by `Ty`: Bool red, Number green, String magenta, Vec3
  yellow, Entity cyan, Json grey-blue, Any grey. A wire takes the colour of its source. Dropping a wire on empty
  canvas opens the palette **filtered to nodes that accept that pin type** (UE behaviour). Illegal connections (type
  `!feeds`) show a red "no" cursor and a tooltip "Number cannot feed String".
- **Right-click palette** (also Space and double-click on empty canvas): searchable, categorised, context
  sensitive. Entries come from three generators, in this order:
  1. `logic-core` node kinds (`Events`, `Flow`, `World access`, `Data`, `Math`, `Vec3`, `Effects`): built from the
     `NodeKind` list and `pins(kind)` so the palette and the validator agree. Parameterised kinds (`Action`,
     `Message`, `Timer`, `Find`, `Get`, `Set`, `Math op`, `Compare op`) show a small inline editor on the node;
     `Get`/`Set` path fields offer a dropdown from `editor.components` (Transform.translation.y ...) of the
     attached entity, falling back to free text.
  2. **Commands**: one palette entry per control command from the engine's command registry (name, description,
     param schema), under `Commands > <group>` (`time.scale`, `sound.play`, `vfx.spawn`, `look.set`, `ai.*` ...). A
     chosen command becomes a `Command { id, params }` node with one data pin per schema parameter (the `"$name"`
     placeholder mechanism already exists). Commands that are editor-only (`editor.*`) are hidden.
  3. **Scripts**: functions found by parsing `scripts/*.ruspy` for `fn name(args)` (a small scanner in the engine:
     `logic.scripts` command returns `[{file, function, args}]`), under `Scripts > <file>`; becomes
     `Script { file, function, args }` with typed any-pins.
  Context filter: with an entity-typed wire dragged out, show `Get`, `Set`, `Script` that take an entity; with a
  flow pin, show flow and effect nodes only; "Context sensitive" checkbox in the popup (default on).
- **Details panel (right of canvas, or in the dock Details)**: for the selected node: kind, id, editable
  parameters, default values for unconnected data pins (typed widget: checkbox, number, text, vec3, entity picker
  from the Outliner), documentation line from a `docs()` table per kind; for a selected variable: type, default.
- **Compile and errors**: `Compile` runs on every edit after a 300 ms debounce and on Save. `GraphError { severity,
  node, pin, message }` drives: a red outline and an exclamation badge on the node, a red ring on the pin, the
  message in a **Compiler results** strip at the bottom of the tab (click = select and frame the node), and the
  same lines in the Output panel under Logic. Warnings (unconnected optional, unused node) are yellow. Status
  chip on the tab: `OK`, `2 errors`, `Saved`.
- **Save and hot reload**: Save writes RON to `assets/logic/<name>.logic.ron` via the backend (`write_logic`), then
  calls `logic.reload` so the editor world swaps the graph (the runtime keeps the last good version when the new
  one has errors, already implemented). Format stability: keep field order, comments are lost, so keep a header
  comment the editor re-adds.
- **Play to test**: toolbar `Play` (existing) saves all dirty graphs and levels, builds, launches; `Test in editor`
  fires an event from the toolbar dropdown (`Start`, `Tick x60`, `Action name`, `Overlap with selected`) through
  `logic.fire {entity, event}` on the attached entity and shows the result: the executed path highlighted and
  `Log` output in the Output panel. Time stays paused in the editor world so this is deterministic.
- **Debugging (feasible subset)**: in the editor world, `logic.fire` returns a trace of node ids executed
  (`Runner` already counts steps; add `trace: Vec<u32>` behind a flag). The tab highlights those nodes and wires for
  1 s with a "pulse"; data pins show the last value on hover ("watch"). Live highlighting while the separate Play
  process runs needs a control-port stream (`logic.trace {entity}` polled at 10 Hz from the editor over the game's
  port 0): put this in a later phase, not WP-C's acceptance. Breakpoints are out of scope.
- **Comments / groups**: `Comment { text, rect, colour }` nodes stored in the graph (`comments: Vec<_>` added to
  `Graph`, ignored by the compiler).
- **Scripts**: `.ruspy` opens a text tab with syntax colouring by a tiny tokenizer, line numbers, errors from
  `LogicDiagnostics` (line:col) as red underlines, `Save` = write + auto reload (already polled every 0.5 s).
  A `Functions` list at the left jumps to `fn`s. "Create node from this function" is the palette entry above.

### 4.3 What the backend exposes (all are `editor.*` commands too, for scripted tests)
Add to `EditorBackend` with default bodies (so the mock and old implementers still compile):
`logic_list() -> Vec<LogicFile>` (`{path, name, errors}`), `logic_read(path) -> Result<String /*RON*/, String>`,
`logic_write(path, ron) -> Result<Vec<GraphErrorDoc>, String>`, `logic_create(name, template) -> Result<String,String>`,
`logic_palette() -> LogicPalette` (node kinds with pin tables and docs, commands with schemas, script functions),
`logic_fire(entity, event) -> Result<LogicTrace, String>`. Types go in `editor-proto`: `LogicFile`, `GraphErrorDoc`,
`LogicPalette`, `NodeTemplate { kind_label, category, kind_json, pins }`, `LogicTrace { nodes: Vec<u32>, log: Vec<String> }`.
`editor-ui` depends on `logic-core` directly (it is Bevy-free) for `Graph`, `pins`, `compile`, so validation runs
in the UI without a round trip; the backend is only for I/O, palette sources outside logic-core, firing events.

### 4.4 Pacenote examples the first version must handle
Event start trigger (`OverlapEnter` on a sensor -> `Command sound.play` + `Set Rally.stage_active`), checkpoint
(`OverlapEnter` -> `Emit "checkpoint"`), a `Timer` that spawns a sign, a building's door. All are
`Start/Overlap/Action/Timer -> Branch/Set/Command/Script/Emit/Log` and fit the current node set; the missing
pieces that block real use are Variables (section 4.2) and an entity picker for `Find`.
