# Godot scripting architecture audit (for the ruspy scripting layer)

Source: `/Users/himanshu/codes/game/godot` (shallow clone, commit c51ff06, read-only, not built).
All `path:line` citations are relative to that tree. Lines are from this exact checkout.

One-sentence model: **every Godot thing is an `Object`; an Object optionally owns one `ScriptInstance*`
that is consulted FIRST for set/get/call/notification/property-list; a Node is an Object whose
engine-side behaviour is driven by integer notifications plus `GDVIRTUAL` hooks that forward into the
script; scripts never touch the GPU, they set properties that push to servers by RID.**

## 1. Object / ScriptInstance model

### 1.1 Types (core/object)
- `Script : Resource` (a *class definition*, shared): `core/object/script_language.h:117`.
  Key pure virtuals: `can_instantiate()` :149, `instance_create(Object*)` :156,
  `placeholder_instance_create` :157, `reload(bool keep_state)` :162, `is_tool()` :179,
  `has_script_signal` :185, `get_script_property_list` :193, `get_script_method_list` :192,
  `get_property_default_value` :188, `update_exports()` :190 (editor).
- `ScriptInstance` (a *per-object instance*, owns the member values): `core/object/script_instance.h:38`.
  Interface: `set`/`get` (:40-41), `get_property_list` (:42), `validate_property` (:44),
  `property_can_revert/get_revert` (:46-47), `get_method_list`/`has_method` (:53-54),
  `callp(method,args,argc,CallError&)` (:58), `call_const` (:70), `notification(int, bool reversed)` (:71),
  `get_script()` (:94), `is_placeholder()` (:96), `property_set_fallback/get_fallback` (:98-99).
  `get_property_state()` default impl (`core/object/script_instance.cpp:61`) = every property whose usage has
  `PROPERTY_USAGE_STORAGE`, read through `get()` -> this is the reload-state snapshot (see section 9).
- `ScriptLanguage : Object` (a *language backend*, singleton registered in `ScriptServer`): `script_language.h:212`.
  `ScriptServer` registry :50 (`register_language` :82, global class names `add_global_class` :92).
  Language hooks: `init/finish`, `make_function` (editor "create callback") `script_language.h:272`, `reload_all_scripts`/`reload_tool_script` (GDScript impl at `modules/gdscript/gdscript.cpp:2486/2655`).
- `PlaceHolderScriptInstance` (editor-only stand-in when script cannot run, e.g. non-@tool script
  selected in the editor): `script_language.h:344`. Stores only `properties` + `values` maps (:347-348),
  so exported vars still show/edit/save without executing script code. Created from
  `Object::set_script` when `!can_instantiate() && is_editor_hint()` (`core/object/object.cpp:1065`).

### 1.2 Object <-> ScriptInstance wiring (`core/object/object.cpp`)
- `Object::set_script(Variant)` :1049: delete old instance, `s->instance_create(this)` (:1062) or placeholder
  (:1065), then `notify_property_list_changed()` and emits `script_changed`. Assigning a script to an
  object *is* "attach component". `Object::set_script_instance` :1079 is the raw swap (used by GDScript's own constructor).
- **Priority rule (important for ruspy): script first, native second.**
  - `Object::set` :198 -> `script_instance->set()` first (:204), then GDExtension, then native `set_native`, then `script` / `metadata/` pseudo-props, then (editor) `property_set_fallback`, then `_setv`.
  - `Object::get` :271 mirrors it (:274).
  - `Object::callp` :851 -> `script_instance->callp()` first (:882); on `CALL_ERROR_INVALID_METHOD` it falls through to the native `MethodBind` (:900-912); any other call error (bad arg count/type) is returned as is (:889-893). `free` is intercepted before anything (:853).
  - `Object::get_property_list` :558 -> script properties are appended after native ones (reversed ordering flag :559), then `script` property with `base_script_usage` (:600).
  - `Object::_notification_forward` :989 -> native classes root->leaf (`_notification_forwardv`), then extension, then `script_instance->notification(what, false)`. `_notification_backward` :1009 runs script FIRST with `reversed=true`, then the native chain leaf->root. So a script `_notification(what)` sees the same ordering as a subclass override in C++.
- Method calls from Callables, signals, `call_deferred`, `call_group` all converge on `Object::callp`:
  `Callable::callp` (`core/variant/callable.cpp:44`) -> `obj->callp(method, ...)` (:68).
  Hence **script methods are found by name at call time**; there is no vtable.

### 1.3 GDVIRTUAL (how native engine code calls script overrides)
- `GDVIRTUAL0..N(_name, args)` macros in node.h (`scene/main/node.h:433-444`), generated by
  `core/object/make_virtuals.py`. `GDVIRTUAL_CALL(_ready)` (`core/object/object.h:138`) expands (make_virtuals.py:1-13) to:
  "if the object has a script instance and `has_method(_ready)`, `script_instance->callp(_gdvirtual__ready_sn, ...)`";
  otherwise native/extension virtual. `GDVIRTUAL_IS_OVERRIDDEN(_process)` (object.h:147) = `script_instance->has_method("_process")`.
  This is how `Node::_notification` triggers `_ready/_process/_input` in scripts.

### 1.4 GDScript implementation (modules/gdscript)
- `GDScript : Script` `gdscript.h:57`. Compile-time layout tables:
  `HashMap<StringName, MemberInfo> member_indices` (:87, includes base classes), `member_functions`,
  `_signals` (compiler fills `p_script->_signals[name]` at `gdscript_compiler.cpp:2948`),
  `old_member_indices` (:90, only during reload), `static_variables_indices` (:94).
- `GDScriptInstance : ScriptInstance` `gdscript.h:339`: `Object *owner`, `ObjectID owner_id`, `Ref<GDScript> script`, **`TightLocalVector<Variant> members`** (:351) = member vars as a flat array indexed by `MemberInfo.index`. Linked into `script->instances` via `SelfList` (:355) for reload.
- Instance creation: `GDScript::instance_create` `gdscript.cpp:415` (checks native base compat :422-430) -> `_create_instance` :160:
  1. alloc, `members.resize(member_indices.size())` (:165), `owner->set_script_instance(instance)` (:169);
  2. run `_super_implicit_constructor` (:144, base-first member initializers = the `var x = 5` field inits, the "implicit initializer");
  3. only if `p_argcount >= 0` run user `_init` (:192-194). From `Object::set_script` argcount is 0 -> `_init()` is called with no args.
- `GDScriptInstance::set` `gdscript.cpp:1555`: lookup `member_indices` -> coerce type (`Variant::construct`, :1562-1569) -> if member has a `setter` call it via `callp` (:1573-1576) else write `members[index]`. (This is GDScript `set(v):` property setters; inside the class itself direct member access bypasses the setter, see compiler.) Falls back to static vars, then `_set` script override.
- `GDScriptInstance::callp` :1967: `_ready` special-case runs the `@implicit_ready` function first, which assigns all `@onready` vars, recursively through base scripts (:1969-1972, `_call_implicit_ready_recursively`). Then walks `script -> base` chain looking in `member_functions` (:1974-1981) and calls `GDScriptFunction::call`.
- `GDScriptInstance::notification` :1987: calls the script's `_notification(what)` at ALL levels of the script inheritance chain, base-most first unless `reversed` (:1998-2015).
- `GDScriptInstance::get_property_list` :1750: calls script `_get_property_list()` (returns Array[Dictionary] with name/type/hint/hint_string/usage, parsed at :1795-1822) plus compile-time member properties (:1851 `property_info` pushed from `member_indices`).
- Functions execute on a register VM (`GDScriptFunction::call`, `gdscript_vm.cpp`); not needed for ruspy beyond the fact that `self` is the `GDScriptInstance*`, so `self.x` is `members[idx]` and `self.get_node()` is a method-bind call on `owner`.

## 2. Node lifecycle and SceneTree main loop

### 2.1 Entering the tree (`scene/main/node.cpp`)
- `Node::add_child` :1711 -> `_add_child_nocheck` :1664 (name uniquification, `PARENTED` notification :1699, `CHILD_ORDER_CHANGED` :1707) -> if parent in tree, `_set_tree` :3396.
- `_set_tree` :3396: `_propagate_enter_tree()` (:3410) then, if parent already ready, `_propagate_ready()` (:3413).
- `_propagate_enter_tree` :341: parent-first. Order per node: set tree/viewport/depth; register groups (:355); `notification(ENTER_TREE)` :360; `GDVIRTUAL_CALL(_enter_tree)` :362; signal `tree_entered` :364; `tree->node_added` :366; parent signal `child_entered_tree` :368; then recurse children (:375).
- `_propagate_ready` :323: **children first (post-order)**, then `NOTIFICATION_POST_ENTER_TREE` :331, then if `ready_first` -> `NOTIFICATION_READY` :335 + signal `ready` :336. `_ready` runs once per node (`ready_first`, `request_ready()` :3601 re-arms it).
  Consequence: a parent's `_ready` can rely on all children being ready; `@onready` and `$Child` are valid there.
- `Node::_notification` :68:
  - `NOTIFICATION_PROCESS` :99 -> `GDVIRTUAL_CALL(_process, delta)`; `NOTIFICATION_PHYSICS_PROCESS` :103 -> `_physics_process`.
  - `NOTIFICATION_READY` :255-279: **auto-enable rules**. For each of `_input`, `_shortcut_input`, `_unhandled_input`, `_unhandled_key_input`, `_process`, `_physics_process`: `if (GDVIRTUAL_IS_OVERRIDDEN(x)) set_process_x(true)`; then `GDVIRTUAL_CALL(_ready)` (:279). I.e. "script defines `_process` => node joins the process list". Note this runs *before* the script's own `_ready` body.
- Exiting: `_propagate_exit_tree` :410 (children reverse order first, then `_exit_tree` :425, `tree_exiting`, `NOTIFICATION_EXIT_TREE` backward :431, `child_exiting_tree`), then `_propagate_after_exit_tree` :391 (`tree_exited`).

### 2.2 set_process and process groups
- `Node::set_process(bool)` `node.cpp:1025`: just a bool + (re)registration in a *process thread group* (`_add_to_process_thread_group`). `can_process()` additionally honours `process_mode` (inherit/pausable/when_paused/always/disabled) resolved on ENTER_TREE (:107-).
- `SceneTree::_process_group(ProcessGroup*, bool physics)` `scene/main/scene_tree.cpp:1193`:
  1. `call_queue.flush()` before (:1197); 2. sort nodes only when dirty with `ComparatorWithPriority` = `process_priority`, then **tree order** (`is_greater_than`) (`scene/main/node.h:190-196`, sort at :1205-1213); 3. iterate a *copy* of the vector (:1217) so add/remove during the callback is safe, skipping nodes in `nodes_removed_on_group_call` (:1226) or `!can_process() || !is_inside_tree()` (:1231); 4. per node send `INTERNAL_PHYSICS_PROCESS/PHYSICS_PROCESS` or `INTERNAL_PROCESS/PROCESS` (:1236-1248); 5. flush call_queue again (:1251).
- `SceneTree::_process(bool physics)` :1260 sorts process groups (`ProcessGroupSort` :1378, by `process_thread_group_order`, threaded groups after main) and dispatches (optionally to WorkerThreadPool). Default: everything is in the single main-thread group.

### 2.3 Per-frame order (`main/main.cpp` -> `scene/main/scene_tree.cpp`)
- `Main::iteration()` `main/main.cpp:4964`: loop `physics_process` 0..N times at fixed step (:5044 `main_loop->physics_process`), then once `main_loop->process(delta)` (:5105), then `RenderingServer::sync()` :5120 and `RenderingServer::draw()` :5136/5140.
- `SceneTree::physics_process` :640: `flush_transform_notifications` -> signal `physics_frame` -> `_process(true)` -> `_flush_ugc` -> `MessageQueue::flush()` (:659) -> timers/tweens -> `flush_transform_notifications` -> `_flush_delete_queue()` (:667, deliberately last) -> idle callbacks.
- `SceneTree::process` :689: signal `process_frame` -> `MessageQueue::flush()` (:711) -> `flush_transform_notifications` -> `_process(false)` -> `_flush_ugc` + `MessageQueue::flush()` (:719) -> `flush_transform_notifications` -> pending scene change (:723) -> timers, tweens -> transforms -> `_flush_delete_queue()` (:731) -> `_call_idle_callbacks`.

### 2.4 Deferred calls and deletion timing
- `Object::call_deferredp` `object.cpp:2074` -> `MessageQueue::get_singleton()->push_callp`. `set_deferred` :2078. Signals with `CONNECT_DEFERRED` push `push_callablep` (object.cpp, emit loop, "flags & CONNECT_DEFERRED").
- `CallQueue::flush()` `core/object/message_queue.cpp:224`: paged ring of messages, re-entrant ("pre-advance so this function is reentrant" :248), drops messages whose target `ObjectID` died. Flushed at the three points above, plus per-process-group before/after (`_process_group`).
- `Node::queue_free()` `node.cpp:3503` -> `SceneTree::queue_delete` `scene_tree.cpp:1656` (sets `_is_queued_for_deletion`, pushes ObjectID) -> `_flush_delete_queue` :1646 (`memdelete`) at the END of the frame. The node is still alive and processing for the rest of the current frame (this is why `is_queued_for_deletion()` exists).
- `Node::NOTIFICATION_PREDELETE` (:282) frees owned children etc.; scripts get `_notification(NOTIFICATION_PREDELETE)`.

## 3. Signals

### 3.1 Core (`core/object/object.cpp`, `object.h`)
- Per-object `signal_map: HashMap<StringName, SignalData>`; `SignalData.slot_map: HashMap<Callable, Slot{conn, reference_count}>` (the slot key is the *base* callable so binds are ignored for duplicate detection, :1628).
- Declaration: native `ADD_SIGNAL(MethodInfo("pressed"))` (e.g. `scene/gui/base_button.cpp:651`), user `Object::add_user_signal` :1184, or script-declared (below). `emit_signalp` :1256 / `connect` :1585 validate signal names against (1) native class members, (2) `signal_map`, (3) `script_instance->get_script()->has_script_signal(name)` (:1599-1613, also tolerated if the script is invalid in editor). Emit of an undeclared name is an error in debug (:1288).
- Flags (`object.h:356-360`): `CONNECT_DEFERRED=1`, `CONNECT_PERSIST=2` (save into scene), `CONNECT_ONE_SHOT=4`, `CONNECT_REFERENCE_COUNTED=8`, `CONNECT_APPEND_SOURCE_OBJECT=16`.
- `Object::connect` :1585: callable validity check, signal validity (above), duplicate check (:1628-1637), insert slot.
- `Object::emit_signalp` :1256: `_block_signals` check; **snapshot** all slots to a small stack array under the signal lock (:1281-1297) so disconnect/free during emission is safe; ONE_SHOT slots are disconnected *before* any call (:1300-1313); then for each slot: skip invalid (:1331), optionally splice source object arg (:1338-1355), `CONNECT_DEFERRED` -> `MessageQueue::push_callablep` (:1358) else `callable.callp(args, ...)` (:1361-1364) with `_emitting` flag; call errors are printed with the signal/target names.
- `Callable` = `(ObjectID, method StringName)` or custom callable (lambda, bound, unbound, `callable_mp`): `core/variant/callable.cpp`. `Callable::bindv` :133 appends bound args after emitted ones; `unbind(n)` :146 drops trailing emitted args. Method callables dispatch via `Object::callp`, so they hit the script instance.
- Built-in node signals worth mirroring: `ready`, `tree_entered/exiting/exited`, `child_entered_tree`, `child_exiting_tree` (node.cpp:336, :364, :368, :421-:437), BaseButton `pressed`, `button_down`, `button_up`, `toggled(bool)` (`base_button.cpp:651-654`), Control `gui_input`, `resized`, `minimum_size_changed`, `focus_entered/exited`, Container `sort_children`.

### 3.2 `signal` keyword in GDScript
- Parser makes a `SignalNode` (name + params); the compiler stores `MethodInfo` into `GDScript::_signals[name]` (`gdscript_compiler.cpp:2948`). `GDScript::has_script_signal` `gdscript.cpp:1297` (walks base scripts), `get_script_signal_list` :1331. There is *no per-instance storage*: the first `connect`/`emit` creates the `SignalData` lazily in the owner `Object::signal_map` (`object.cpp:1620-1621`).
- `sig.emit(a)` / `connect(callable)` are `Signal` builtin methods operating on `(owner Object, name)`; `emit_signal("x")` is the string form. Script methods are connected as `Callable(self_owner, "method_name")`.

### 3.3 Persistence in .tscn and editor flow
- Scene text: `[connection signal="pressed" from="Panel/Button" to="." method="_on_button_pressed" flags=3 binds=[...] unbinds=n]` written by `scene/resources/resource_format_text.cpp:1823-1860` (flags omitted when == `CONNECT_PERSIST`; `from`/`to` are NodePaths relative to scene root; optional `from_uid_path`/`to_uid_path` for instanced-scene robustness).
- Packed in `SceneState` (`scene/resources/packed_scene.cpp`): `ConnectionData{from,to,signal,method,flags,binds,unbinds}`; collected at pack time by `_parse_connections` :1218 -- only connections with `CONNECT_PERSIST` are saved (:1241).
- At instantiate, after all nodes and properties exist: `SceneState::_instantiate` loop at `packed_scene.cpp:735-763` resolves both endpoints (`NODE_FROM_ID` macro :227), builds `Callable(cto, method)`, applies `bindv`/`unbind`, and `cfrom->connect(signal, callable, CONNECT_PERSIST | flags | (not main ? CONNECT_INHERITED : 0))`. Missing endpoint => silently skipped (:744).
- Editor Node dock: `ConnectionsDock` (`editor/scene/connections_dialog.cpp`). The dialog `ConnectDialog` picks target node + method; if the method does not exist, asks the language to write a stub: `language->can_make_function()` :502 and `EditorNode::emit_signal("script_add_function_request", target, method, args)` :1084 -> `ScriptTextEditor::add_callback` (`editor/script/script_text_editor.cpp:419`) -> `ScriptLanguage::make_function` (GDScript: `func _on_button_pressed():`). Then `ConnectionsDock::_connect` :1100 is an undo/redo action calling `source->connect(signal, callable, flags)` with `CONNECT_PERSIST` (flags set by dialog). Saved by the scene save as above.

## 5. UI (Control) and CanvasItem drawing

### 5.1 Layout model (`scene/gui/control.cpp`)
- Each Control has 4 anchors (0..1 fraction of parent rect) and 4 offsets (pixels): `data.anchor[4]`, `data.offset[4]`.
  `Control::_size_changed` `control.cpp:2265`: for each edge `edge_pos[i] = offset[i] + anchor[i] * parent_rect.size[i&1]` (:2270-2274); position/size derived; clamped by `get_combined_minimum_size()` / maximum with `h_grow/v_grow` direction (:2279-2310); updates cached rect, `NOTIFICATION_RESIZED` (:2346) and `canvas_item_set_transform` (via `_update_canvas_item_transform`, :838).
- Setters: `set_anchor` :860, `set_offset` :900, `set_anchors_preset` :1233 (full rect, center, etc.), `set_position` :1555. All end in `_size_changed()` (maybe deferred via `layout_pending_*`).
- Minimum size is a cached bottom-up value: `get_combined_minimum_size` :2240 (`_update_minimum_size_cache` :2231 = max(virtual `get_minimum_size()`, `custom_minimum_size`)). `update_minimum_size()` :1971 invalidates up the parent chain and schedules `_update_minimum_size` (:1955) which, if changed, calls `_size_changed()` and emits `minimum_size_changed` (-> parent Container re-sorts).
- Size flags (`control.h:79-87`): `SIZE_FILL=1`, `SIZE_EXPAND=2`, `SIZE_SHRINK_CENTER=4`, `SIZE_SHRINK_END=8`, plus `size_flags_stretch_ratio`; per axis (`set_h_size_flags` :2366). Only meaningful when the parent is a Container.

### 5.2 Containers
- `Container::queue_sort()` `container.cpp:180`: set `pending_sort`, `callable_mp(this,&Container::_sort_children).call_deferred()` (so many mutations coalesce into one sort at the next MessageQueue flush).
- `Container::_sort_children` :116: `update_minimum_size()`, `PRE_SORT_CHILDREN` notification + signal, **`NOTIFICATION_SORT_CHILDREN`** + signal `sort_children`. Subclasses implement layout in `_notification(NOTIFICATION_SORT_CHILDREN)`.
- Helper `Container::fit_child_in_rect(child, rect)` :133 applies the child's size flags (FILL vs shrink begin/center/end, min/max size, RTL) and calls `child->set_position/set_size`. `Container::as_sortable_control` (:190) filters non-Control, top_level, invisible children.
- `MarginContainer` (`margin_container.cpp:109`): every child gets `fit_child_in_rect(c, Rect2(ml, mt, w - ml - mr, h - mt - mb))`, margins come from theme constants.
- `BoxContainer::_resort` (`box_container.cpp:47`): one pass computes min sizes + stretch ratios of children (`stretch_space`, `stretch_ratio_total`, :56-59 ...), distributes extra space to EXPAND children by ratio, then `fit_child_in_rect` for each. HBox/VBox are the same class with `vertical` flag.

### 5.3 Theme lookup
- `Control::get_theme_color/constant/font/stylebox` (`control.cpp:3993`, `get_theme_constant` ~:4015). Order: (1) per-control override map (`data.theme_color_override`) when `theme_type` is empty/own class/type variation (:3999-4003); (2) per-control cache `theme_color_cache[type][name]` (:4005); (3) miss -> `data.theme_owner->get_theme_type_dependencies(this, type, ...)` then `get_theme_item_in_types(...)` (`scene/theme/theme_owner.cpp:178,228`): walks nearest ancestor Control/Window `theme` first, then project theme, then default theme, and within each, walks the class inheritance chain + type variations (a Button looks up "Button" -> "BaseButton" -> "Control"). Result stored in the cache. `NOTIFICATION_THEME_CHANGED` (`control.cpp:3804,3886`) invalidates caches (`_invalidate_theme_cache` :3808) and widgets re-read in `_notification`/`_update_theme_item_cache`.

### 5.4 Buttons and signals
- `BaseButton::gui_input` :60 -> `on_action_event` :233 handles press/release/toggle/hover state machine (`status.pressed/hovering/pressed_down_with_focus`), `action_mode` PRESS or RELEASE (default release) decides when to fire. ### 5.5 How scripts drive UI
- Typical: `@onready var label: Label = %ScoreLabel` (or `$HUD/Score`), then `label.text = str(score)`; `button.pressed.connect(_on_pressed)` or the editor connection in the .tscn. Property setters (e.g. `Label.set_text`) call `update_minimum_size()` + `queue_redraw()`; no script code participates in layout/draw unless it overrides `_draw`/`_get_minimum_size`/`_gui_input`.
- `%Name` unique names: node flag `unique_name_in_owner` (`node.cpp:2280`), registry `owner->data.owned_unique_nodes` (:2256-2278, key is prefixed with `%`), lookup in `get_node_or_null` (:1962-1972): `%Name` resolves against the node's own scene `owner`. Works at any depth, independent of moves within the scene.

### 5.6 CanvasItem drawing -> RenderingServer
- `CanvasItem` (`scene/main/canvas_item.cpp`) owns `RID canvas_item` created in ctor via `RenderingServer::canvas_item_create()` (:1897) and freed in dtor (:1902). Both `Node2D` and `Control` are CanvasItems.

- Transform: Node2D `canvas_item_set_transform(rid, xform)` (`scene/2d/node_2d.cpp:143,382`); Control the same from layout (`control.cpp:838`); `set_visible` -> `canvas_item_set_visible` (:103); `set_modulate` -> `canvas_item_set_modulate` (:570).

- `_redraw_callback` :144: if `draw_commands_dirty` -> `canvas_item_clear(rid)` (:151); if visible in tree: sends `NOTIFICATION_DRAW` (:173), emits `draw` signal (:174), then `GDVIRTUAL_CALL(_draw)` (:175) (script override). ## 6. Rendering from the script's point of view

- Scripts never see GPU handles. Scene nodes hold `RID`s into the RenderingServer (the "server" in Godot's server architecture) and push state by command; the server renders in `RenderingServer::draw()` (`main/main.cpp:5136`) from its own scene copy. Resources (`Mesh`, `Material`, `Texture`) own RIDs too and are reference counted.
- 3D: `VisualInstance3D` ctor `instance_create()` + `instance_attach_object_instance_id(instance, object_id)` (`scene/3d/visual_instance_3d.cpp:213-214`, free in dtor :220), `set_notify_transform(true)` (:215) so it receives transform notifications.
  - `NOTIFICATION_ENTER_WORLD` -> `instance_set_scenario(instance, world3d scenario)` (:93); EXIT_WORLD -> null scenario (:115).
  - `set_base(rid)` :201 -> `instance_set_base` (the mesh/light RID). `MeshInstance3D::set_mesh` (`mesh_instance_3d.cpp:120`) calls `set_base(mesh->get_rid())` (:131) and connects `changed`; `set_surface_override_material` (:375) -> `instance_set_surface_override_material` (:381).
  - Transform propagation: `Node3D::set_transform` `node_3d.cpp:391` stores local transform, marks Euler cache dirty, `_propagate_transform_changed(this)` :112 recurses to Node3D children (skipping top_level), marks global dirty bits (:139) and, if `notify_transform`, adds the node to `SceneTree::xform_change_list` (:127-137). `SceneTree::flush_transform_notifications` (`scene_tree.cpp:201`) later sends `NOTIFICATION_TRANSFORM_CHANGED` to each listed node exactly once per flush (called ~4x per frame, see 2.3). `VisualInstance3D::_notification(TRANSFORM_CHANGED)` (:99-101) then does `instance_set_transform(instance, get_global_transform())`.
  So: script sets `position`/`transform` -> lazy dirty bits -> one notification per node per flush -> one RS call. Reading `global_transform` recomputes lazily from parents.
- 2D: `Node2D::set_position` etc. call `_update_transform()` that pushes `canvas_item_set_transform` immediately (`node_2d.cpp:143`) and notifies `NOTIFICATION_LOCAL_TRANSFORM_CHANGED`.
- Rule for ruspy: **script properties = authoring data; a native "sync" system owns the render handles.** Setting a script variable never implies an engine call unless it is a property setter on a native node.

## 8. Node paths and scene instancing

- `NodePath` (`core/string/node_path.h`): vector of StringName segments + optional property subpath (`Node:position:x`) + absolute flag. `Node::get_node_or_null(path)` `node.cpp:1922`:

- Owner: `Node::set_owner` :2303. Nodes created from a PackedScene have `owner = scene root`; owner is what defines which nodes get saved into the scene and what `%Unique` is relative to. Runtime-added nodes have no owner unless set.
- PackedScene: `PackedScene::instantiate(edit_state)` `packed_scene.cpp:2582` -> `SceneState::_instantiate` :227. - Groups: `Node::add_to_group(name, persistent)` `node.cpp:2490` stores in `data.grouped`; registered in tree on ENTER_TREE (`_propagate_enter_tree` :355 -> `SceneTree::add_to_group` `scene_tree.cpp:175`). `SceneTree::group_map: name -> SceneTreeGroup{nodes Vector<Node*>}`. `call_group(group, method, ...)` -> `call_group_flagsp` `scene_tree.cpp:362`: copies the node list, `_update_group_order` (tree order), `callp` on each (flags: `GROUP_CALL_DEFERRED`, `REVERSE`, `UNIQUE`), `notify_group` :455, `get_nodes_in_group`. They are children of `/root`, so also reachable as `/root/Name` or `get_node("/root/Name")`.
- Scene change: `SceneTree::change_scene_to_file/packed/node` :1719-1738 -> pending id -> `_flush_scene_change` :1691 executed in `process()` (:723): frees old `current_scene` and adds the new one.

## 9. Hot reload of scripts

- Trigger: editor save / file-system change calls `GDScriptLanguage::reload_scripts(Array)` `gdscript.cpp:2518` (all scripts: `reload_all_scripts` :2486; single tool script: `reload_tool_script` :2655). Debug/tools builds only (`#ifdef DEBUG_ENABLED`).
- Algorithm (:2518-2619): collect root scripts (subclasses reload via their root, :2525-2529); for each script and its dependents that have instances, `_prepare_script_for_reload` (:2622, TOOLS_ENABLED): for every live `GDScriptInstance` (`p_script->instances` list) `instance->get_property_state(state)` (:2628 -> all `STORAGE` properties, script_instance.cpp:61) is stored in `to_reload[script][ObjectID]`, then `owner->set_script(Variant())` detaches. Same for placeholders (:2636-2643) and any `pending_reload_state` from earlier failures (:2649).
- Then `scr->reload(true)` (`GDScript::reload(bool p_keep_state)` :745) re-parses/compiles, rebuilding `member_indices`, `member_functions`, `_signals`; `old_member_indices` retained during compile for `reload_members` (:2057, remaps slots by name and type when the instance is kept in place).
- Restore (:2579-2615): `ObjectDB::get_instance(oid)` (skip if freed) -> `obj->set_script(scr)` (creates a fresh instance: runs implicit initializers and `_init`) -> for each saved `(name,value)`: `script_inst->set(name, value)` (:2605) which re-applies type coercion; if the new script failed to compile the state stays in `pending_reload_state` (:2595) and is retried on the next successful reload. Placeholders use `property_set_fallback` (:2599-2602).
- `GDScript::reload` refuses when instances exist and `keep_state==false` (:759-764) -- the explicit contract. `reloading` flag guards recursion (:746-750).
- Not preserved: non-exported members (no STORAGE usage), signal connections made at runtime to the script's callables are by (ObjectID, method name) so they survive; connection flags `PERSIST` ones come from the scene. Running coroutines (`await`) are invalidated.
- Takeaway: Godot's reload = "snapshot storable properties by name, detach, recompile, re-attach, set by name with type coercion". Simple and robust because state is a name->Variant bag.

## What to copy into a Rust/Bevy ECS engine (ranked)

1. **Script = component attached to an entity, with a stable "storable property bag".** `ScriptInstance` maps to a `Script { source: Handle<RuispyScript>, props: HashMap<StrId, Value> (or slot array indexed by script layout) }` component. The Handle plays Godot's `Script` role (compiled class: member layout, function table, signal list, exports); the component is the `GDScriptInstance` (flat `Vec<Value>` of members indexed via the layout, exactly `members[MemberInfo.index]`, gdscript.h:351). Attach = insert component (== `Object::set_script` `object.cpp:1049`: replace instance, then fire a "properties changed" event). Every other feature (inspector, save, hot reload, scene load) is defined over this bag. Mirror the *order*: script first, native second, for `set/get/call` on `Name.prop` so a script can shadow engine properties and fallbacks to native happen only on "no such member".

2. **Name-based dispatch with a virtual-hook table cached at compile time (GDVIRTUAL).** At script compile, resolve which of `_init/_ready/_process/_physics_process/_input/_unhandled_input/_enter_tree/_exit_tree/_gui_input/_draw/_notification` exist and store them as `Option<FnId>` on the script asset. A Bevy system per hook iterates `Query<(&mut Script, ...)>` with a precomputed `has_process` marker. Reproduce the **auto-enable** rule (node.cpp:255-279): when an entity gains/changes a Script, insert marker components `ScriptProcess`, `ScriptPhysicsProcess`, `ScriptInput`, `ScriptUnhandledInput` from `has_hook()`. Systems then use `With<ScriptProcess>` and cost nothing for scripts without the hook. Calls from native code to script = `script.call_hook(HookId, args)` returning `Unhandled`/`Ok` so native defaults still run (Godot's `GDVIRTUAL_CALL` returns false when not overridden).

3. **Lifecycle ordering identical to Godot: enter parent-first, ready children-first, deferred free at end of frame.** Implement `OnEnterTree` (parent before child), `OnReady` (post-order, once per entity, with a `ReadyDone` marker) as Bevy observers on `Add<Script>` / `ChildOf` changes plus a `ScriptLifecycle` schedule set; exports must be written before enter (scene load sets props before spawn commands apply, `packed_scene.cpp:456`). `queue_free` = `commands.entity(e).insert(QueuedFree)` and a last-in-`Last` system despawns after all process/physics/timers (scene_tree.cpp:667/731 "should happen last"); `is_queued_for_deletion` is the `With<QueuedFree>` filter. Process order = `process_priority` then hierarchy (DFS) order: store `ProcessOrder(i32)` + a cached DFS index, sort only when dirty (scene_tree.cpp:1205-1213); iterate a snapshot and skip entities despawned mid-loop (:1217-1231).

4. **Signals as typed events routed through a per-entity connection table, with deferred and one-shot modes.** A `Signals` component `HashMap<StrId, SmallVec<Connection{target: Entity, method: StrId, flags, binds, unbinds}>>` on the *source* entity; `emit(entity, name, args)` snapshots the vector first (object.cpp:1281-1297), removes ONE_SHOT before calling (:1300-1313), runs immediate connections inline via the script `call(target, method, args)`, and for `DEFERRED` pushes a `Command` / `Event` into a `DeferredCalls` queue flushed at the same points as Godot's MessageQueue (process start, after process, after physics). The `signal` keyword just registers names/param lists on the script asset (gdscript_compiler.cpp:2948) and validates `connect/emit` names. Native widgets emit the same way (`Pressed`, `Toggled`, `GuiInput`) by calling `emit` — and ALSO send a Bevy `EntityEvent` so Rust systems/observers can listen without scripts. Keep `bind`/`unbind` for editor-authored connections.

5. **Deferred call queue ("MessageQueue") as a first-class scheduling primitive.** `call_deferred(entity, method, args)`, `set_deferred`, deferred signal connections, deferred container re-sort and deferred redraw all use the same ring queue flushed at fixed points (message_queue.cpp:224, re-entrant, drops dead targets). In Bevy: a `Resource DeferredCalls(Vec<Call>)` drained by an exclusive system at the three Godot flush points; entity validity re-checked at drain time. This is how scripts safely mutate the hierarchy from callbacks and how layout/redraw coalesce (`queue_sort`, `queue_redraw` both use a `pending_*` bool + one deferred call, container.cpp:180, canvas_item.cpp:541).

6. **Input in four ordered stages with a handled flag and reverse-tree-order delivery.** Resource `InputHandled(bool)` reset per event. Stage order exactly: `_input` -> UI/GUI hit-test (`Interaction`/bevy_ui picking) -> shortcut -> `_unhandled_key_input` -> `_unhandled_input` (viewport.cpp:3563-3585, 3651-3664). Each script stage is a system iterating `Query<..., With<ScriptInput>>` in **reverse hierarchy order** and `break`ing when `InputHandled` is set (scene_tree.cpp:1477-1478). GUI stage: hit-test topmost node, then bubble to ancestors applying `MouseFilter {Stop, Pass, Ignore}` (viewport.cpp:1759-1795) -- implement `MouseFilter` as a component on UI entities; Stop sets Handled for pointer events. Give `Control::gui_input` the order: signal first, then script hook, then native (control.cpp:2623-2640).

7. **Paths by Name + owner-scoped unique names; groups as tag components.** `NodePath` resolution (node.cpp:1922) maps to `get_node(entity, "A/B/../C")` via `Name` + `Children` (Bevy `ChildOf`), with a per-scene-root `UniqueNames: HashMap<StrId, Entity>` component for `%Name` (node.cpp:2256-2278). `$Path` and `%Name` become ruspy parse-level sugar compiled to `get_node("...")` with a constant path -- keep `@onready` semantic by letting `var x = $Foo` / `onready var` assign right before `_ready`. Groups = a `Groups(SmallVec<StrId>)` component plus a `Resource GroupIndex: HashMap<StrId, Vec<Entity>>` maintained on add/remove/despawn observers; `call_group` snapshots in hierarchy order. Autoloads = entities spawned under the root before the main scene and also registered as ruspy globals (`main.cpp:4593-4606`).

8. **Property list with usage flags drives inspector, save/load and hot reload from ONE description.** Define `PropInfo{name, ty, hint(Range/Enum/File/NodePath/...), hint_str, usage: Storage|Editor|Group|Category}` per exported variable. `@export` annotation in ruspy fills it at compile time (parser :4664). The editor inspector lists `usage & Editor`; the scene/save serializer writes `usage & Storage` values that differ from defaults; hot reload snapshots `usage & Storage` (script_instance.cpp:61). Placeholder behaviour: a non-running script (editor mode, failed compile) still carries a prop bag so exports remain editable/saveable (script_language.h:344). Map to Bevy reflection: store values as `serde`-able `Value`, expose via your existing `ecs.set` inspector path.

9. **Scene format = nodes + property sets + persisted connections, instantiated in a fixed order.** Store per node `{name, type|instance, parent, owner, props, groups}` + top-level `[connection signal from to method flags binds]` entries with paths relative to scene root (resource_format_text.cpp:1823). Instantiate: spawn entities, set all props (script attached as a property `script = ...`, init members, then props), add groups, resolve connections last (packed_scene.cpp:735-763), only then attach to the live hierarchy. Connections referencing missing nodes are skipped silently. The editor's "connect signal" dialog should append to this list and offer to generate a stub `func on_x_pressed():` in the script (connections_dialog.cpp:1084, `make_function`).

10. **UI = retained tree with deferred, coalesced layout and cached theme lookup; scripts only set properties.** Control semantics to copy onto bevy_ui `Node`s: anchors+offsets (`pos = offset + anchor*parent_size`, control.cpp:2270), min-size cache that invalidates upward and triggers a single deferred container sort (control.cpp:1971, container.cpp:116-131), size flags SHRINK/FILL/EXPAND + stretch ratio via `fit_child_in_rect` (container.cpp:133), `Box/Margin` containers as notification handlers, theme item lookup = override map -> per-node cache -> ancestor `Theme` -> project theme -> default, walking class/type-variation names (control.cpp:3993; theme_owner.cpp:178,228), `pressed/toggled` signals fired after the `_pressed` hook (base_button.cpp:210-231). For custom drawing, keep Godot's rule: draw commands are *retained* per item, only rebuilt on `queue_redraw` (canvas_item.cpp:144-175) -- map `_draw` to a `DrawCommands` component filled by a script call and consumed by a render-extract system. Likewise scripts never touch GPU: transform setters mark dirty and a single sync system pushes `GlobalTransform` to render entities once per frame (the `xform_change_list` + `NOTIFICATION_TRANSFORM_CHANGED` pattern, node_3d.cpp:112-137, scene_tree.cpp:201), which Bevy's change detection (`Changed<Transform>`) already gives you for free.

### Hot-reload note for ruspy (derived from section 9)
Snapshot `Storage` props per entity by name -> remove Script component -> recompile asset (keep old layout for diagnostics) -> re-insert component (runs member initializers + `_init`) -> `set` each prop with type coercion -> on compile failure keep the snapshot as `PendingReload` and retry on next success (gdscript.cpp:2595, 2622-2655). Do not fire `_ready` again on reload (Godot doesn't, because the node stays in the tree and `ready_first` is already false; node.cpp:3601).

### Things Godot does that we should NOT copy
- String-keyed `callp` for every native->script call: precompute `FnId` hooks (item 2).
- A single-threaded global `MessageQueue` with unbounded growth between flushes: cap per-frame and log.
- Property `Variant` boxing everywhere: ruspy values should be a compact enum with typed slots for exports.
- Per-node `Object` identity via `ObjectID` + `ObjectDB` lookups: Bevy `Entity` generation already gives the "is target alive" check used in `Callable::callp` (callable.cpp:60-67).
