# Competition: Summer Engine

What Summer Engine says about itself, and what that means for Hull. Read on 18 November 2026 from its home page,
pricing page and the `llms.txt` it publishes for agents. Its documentation, roadmap, changelog and blog were not
read. Everything in section 1 is their own claim, not something tested.

## 1. What they offer

| | Summer Engine |
|---|---|
| What it is | A free desktop game engine for macOS and Windows, 2D and 3D, "built to be driven by people and AI agents". |
| Promise | "Describe the game you want and Summer builds it with you in a full engine." They set this against browser tools that "make web toys". |
| Foundation | "A desktop engine compatible with Godot 4". Games are GDScript, C++ or C#. The app's source is not public; the agent layer (CLI, MCP server, skills) is MIT. |
| How a game is made | Chat with their agent, or bring your own (Claude Code, Codex, Cursor) through a free MCP server with more than 80 tools. Output is scenes, scripts and code. |
| Assets | Generated through hosted third-party models (3D models and rigging, images, video, voice, sound effects, music, animation), plus a library they count at over 200,000 free assets and 130 templates. |
| Testing | Through MCP the agent can run the desktop game and inspect errors and screenshots. |
| Editing after generation | "Play it, change anything, and keep going", a scene editor, natural-language scene building. No version history, branching or experiments are mentioned; the only undo described is for store and team settings. |
| Shipping | Windows, macOS, Linux, iOS, Android and web are listed (their own pages disagree about Linux). "You own the code and assets you create", with no royalties. |
| Services | Hosted AI, multiplayer servers and matchmaking, publishing to their own games site, analytics. |
| Pricing | Free app with a small one-time credit; Pro 20 USD a month; Pro+ 60; Ultra 200; Enterprise. Hosted AI, generation, multiplayer and cloud are what is paid for. |
| Stated gaps | No gameplay recording, no import from Unity or Unreal, VFX pipeline "in development". |

## 2. Where Hull is different

| | Summer Engine | Hull |
|---|---|---|
| Checking the AI's work | Run the game, look at errors and screenshots | The same, plus a deterministic simulation that runs without a screen (thousands of frames a second in a test), golden images, sound measured offline, frame budgets |
| Checking a single piece | Play the game | A bench for each sound, character, animation, screen and effect |
| Tuning | Edit in the engine's editor | Sliders generated from schemas, written straight to JSON or to the code's own literals, live |
| History | Not mentioned | On by default: every change recorded with its author, parallel experiments, side-by-side compare, adopt, merge |
| What ships | A native engine export per platform | One JavaScript file; the web is the first platform, and the desktop wraps the same build |
| Language | GDScript, C++, C# | TypeScript, the language models write most and check best |
| Art and sound | Generated by hosted models, plus a large library | Made in code by default (geometry, textures, sound recipes); AI-generated assets are a later track |
| Who runs the AI | Their agent, or yours through MCP | Yours through MCP (hosted by the Hull app), or Marl AI through Marl's API |
| Where the project lives | Not stated clearly | Local today; on Marl's servers for customers |
| Code and sharing | The user owns the code, free app | Marl holds the code. Games are free to play and to share with anyone, the way FlutterFlow works. |

## 3. What to take from it

1. **Bring your own agent is their headline.** Hull's MCP server (hosted by the app) assumes this; it should be
   said as plainly, and the MCP tool list should be something a customer can read.
2. **"Web toys" is the attack on a web-first engine.** The answer has to be visible in the proving game: a real 3D
   action game, installed natively, 60 frames a second, with saves, a gamepad and a settings screen. That is what
   M4 and M6 are for.
3. **History and experiments are a real gap in what they describe.** It is the part of Hull to show first.
4. **Assets are their strength and Hull's hole.** A game made only of generated geometry has a house look. AI-generated
   assets (models, images, voice, music) are a planned later track in `PLAN.md`. Config kinds already allow imported files (`gltf` bodies, `sample` sounds, image textures), so the
   door is open.
5. **Their model is "free app, you own the code".** Marl's is "we hold the code; your game is free to play and to
   share with anyone". The second half is the thing to lead with: a link anyone can open, with nothing to
   install. Customers will still ask whether they can take their code out, and what it costs (question Q3 in
   `PLAN.md`).
6. **They sell multiplayer, mobile export and analytics.** All three are outside Hull's first version. Mobile is
   the cheapest to add later (the build is already a web page); multiplayer is the most expensive.
