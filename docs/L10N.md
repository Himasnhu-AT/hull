# Localization (`engine::l10n`, feature `l10n`)

String tables in small text files, a tiny API, hot language switching, a pseudo-locale for
layout testing, and missing-key reports an AI agent can read over the control port. Feature
`l10n` is on by default; `EnginePlugin` adds `L10nPlugin`.

## Files

`<assets>/locale/<lang>.ftl`, one per language (file stem = code). The engine embeds its own
tables (`assets/locale/{en,de,fr}.ftl` of this crate: menus, settings, pause, controls,
accessibility); a game's files are read at startup and its keys win. Format — a Fluent subset:

```ftl
# comment
language-name = Deutsch
hud-score = Punkte: { $score }            # `{ $n }` and `{n}` are both arguments
hud-lives = { $n ->
    [0] Keine Leben
    [one] Ein Leben
   *[other] { $n } Leben
}
long-text = First line
    second line                           # indented lines continue the value
brace = Literal {"{"} brace
```

Selects match an exact number (`[0]`), then the language's CLDR plural category (`zero one
two few many other`; rules for en/de/nl/sv/it/es…, fr/pt, ru/uk/be, pl, cs/sk, ar, and
ja/zh/ko/th/vi/tr), then a string (`[male]`), else the `*` default. One variant per line.
Not supported: terms, message references, attributes, functions.

Tables can also live in code: `app.add_locale_table("en", include_str!("../assets/locale/en.ftl"))`.

## API

```rust
use engine::prelude::*;                      // tr, tr_args, Tr, Locale
let s = tr("menu-play");                      // "Play" / "Spielen"
let s = tr_args("hud-lives", &[("n", 3)]);    // "3 lives"
let s = engine::l10n::tr_with("greet", &[("name", "Ana".into()), ("n", 2.into())]);
commands.spawn((Text::default(), Tr::new("hud-score").arg("score", 10)));   // re-localizes on switch
q.single_mut()?.set_arg("score", 11);         // changed Tr → text updated
world.resource_mut::<Locale>().set("de")?;    // hot switch ("de-AT" → "de")
```

- Lookup: current language → fallback (`en`) → the key itself. Every miss is recorded.
- `Locale::missing()` / `l10n.missing`: runtime misses (`"de:hud-score"`), keys of the
  fallback each language lacks (`untranslated`), keys only a translation has (`orphans`),
  parse errors with file:line.
- Engine screens translate their literals: `ui::tl("Settings")` finds the key whose fallback
  text is "Settings" and returns the current language's text (borrowed and free when the
  language is the fallback). `theme::text/title/eyebrow`, buttons, tabs, setting rows, choice
  options, About-card help (`ui::tl_fmt` with arguments) and toasts all go through it, so a
  game's own labels translate too as soon as its table has them. On a switch the open screen
  is rebuilt and every `Tr` text is refreshed.
- `pseudo`: generated from the fallback table — accented, ~30 % longer (vowels doubled, `~`
  padding), wrapped in `[ ]`, placeables untouched — to spot hard-coded strings and overflow.
- The language: settings "Interface" → **Language** (options = tables found at startup),
  `--lang <code>` (dev builds), `$LC_ALL` / `$LANG` when nothing is saved; saved in
  settings.json section `"locale": {"lang": "de"}`.

## Control commands (feature `devtools`)

| command | params | does |
|---|---|---|
| `l10n.set` | `lang` | switch language (error lists what exists) |
| `l10n.list` | – | current, fallback, languages with names |
| `l10n.missing` | `clear?` | runtime misses, untranslated / orphan keys, parse errors |
| `l10n.tr` | `key`, `args?` (object) | translate in the current language |
| `l10n.reload` | – | re-read `<assets>/locale/*.ftl` (hot reload while editing) |

## Tests

- `cargo test --lib l10n` — parser (args, selects, continuation lines, string literals,
  errors), plural rules, fallback chain, missing/untranslated/orphan report, pseudo, and that
  the engine's own tables parse cleanly and are complete in every language.
- `cargo test --test actions` (`localization_switch_fallback_pseudo_and_persist`) — on the real
  headless app: code tables, `Tr` re-localization on a switch, control commands, engine literal
  translation, pseudo, the Language row, persistence across runs.

## Cost

- `tr`/`tr_literal`: one uncontended `RwLock` read + a hash lookup; `tr_literal` in the fallback
  language returns the input borrowed (no lookup). Strings are produced when screens are built,
  not per frame. `Tr` texts update only when changed or after a switch (`Changed<Tr>` / a
  generation counter).
- A switch rebuilds the open screen once (same cost as opening it).

## Known limits

- The view `tr()` reads is process-global (one `Locale` per process; tests that switch
  languages serialize).
- Engine tables: English, German, French. No CJK/RTL: the embedded Barlow fonts are Latin only
  (a game shipping CJK must `theme::override_font` with a font that has the glyphs); no
  bidirectional layout.
- Number/date formatting is plain (`1234.5`), not locale-aware.
- Language names on the settings row are fixed at startup (tables added later still work via
  `l10n.set`).
